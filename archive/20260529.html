Opening

IDE는 지고
Agent OS가 떠오른다

Thesis

요즘 더 자주 보는 것은 코드보다 agent와의 대화 맥락이다

대화 context

무엇을 시켰고, 어떤 답을 받았고, 어디서 방향이 바뀌었는가?

작업 이력

어떤 파일을 고쳤는지보다 어떤 시도와 검증이 지나갔는지가 중요해진다.

중심 이동

코드를 직접 붙잡는 방식에서 agent의 상태와 판단을 관리하는 방식으로 바뀐다.

코드 중심에서 agent 중심으로
Pain Point

창은 많아졌는데 상태는 내 머리 안에 있다

여러 프로젝트를 동시에 처리하면 VS Code 창, 터미널, 원격 세션이 흩어지고 마지막 작업 상태를 사람이 다시 찾아야 합니다.

Codex Desktop

프로젝트는 폴더가 아니라 작업 단위가 된다

대화, 명령어, 변경사항, 테스트, 실패한 시도가 프로젝트 세션 안에 남습니다. 파일 편집과 터미널은 그 세션 안의 도구가 됩니다.

Shift

중심이 바뀐다

파일 중심

무슨 파일을 열었는지 기억한다.

창 중심

어떤 IDE 창이 어떤 작업인지 찾는다.

세션 중심

작업의 상태와 기록을 thread에서 이어간다.

운영 중심

agent가 작업을 나누고 검증하고 인수인계한다.

Remote Control

하나의 기기에서 모든 원격 서버를 관리한다

GPU 서버, 회사 서버, VM, container, CI 환경까지 작업 표면으로 들어옵니다. 심지어 폰에서도 상태 확인과 다음 지시가 가능합니다.

님폰없? 이제는 폰으로 서버 못 봄?

Orchestration

믿을 만한 작업 기록이 쌓이면 인수인계가 가능해진다

인간 관리자가 모든 맥락을 들고 있는 구조에서, agent 관리자 또는 orchestrator가 여러 subagent에게 작업을 나눠주는 구조로 이동합니다.

Handoff

agent에게 넘길 수 있는 것은 코드가 아니라 맥락이다

의도

왜 이 변경을 하는지, 목표가 무엇인지 남긴다.

거절한 선택지

시도했지만 버린 접근을 기록해 반복 탐색을 막는다.

검증 기준

무엇이 통과되어야 완료인지 명확히 남긴다.

Complex Project

submodule 18개짜리 ROS workspace는 IDE만으로 운영하기 어렵다

빌드 로그, package 관계, message 정의, launch 파일, simulation과 real robot 설정까지 프로젝트 이해 과정이 누적되어야 다음 작업자가 이어받을 수 있습니다.

Meaning

IDE가 사라진다는 뜻이 아니다

IDE는 Agent OS 안에서 쓰이는 도구 중 하나가 된다

Cursor, VS Code, Claude Desktop, 터미널, 원격 서버는 모두 남습니다. 하지만 중심은 편집기가 아니라 작업을 기억하고 검증하는 운영 환경입니다.

Tip

Claude Desktop과 Cursor도 여전히 쓸모가 있다

하나의 도구로 통일하는 것이 목표가 아닙니다. 긴 문맥 정리, 빠른 편집, 제한된 세션 등 도구별 역할을 분리합니다.

Security

공용 PC에 토큰을 남기면 Agent OS 시대에는 더 위험하다

agent는 파일을 읽고, 서버에 접속하고, git push와 배포까지 할 수 있습니다. 어떤 도구에 어떤 권한을 줄지 분리해야 합니다.

Summary

오늘의 핵심

1

여러 프로젝트와 세션이 동시에 돌 때 IDE 중심 방식은 피로해집니다.

2

Agent OS는 workspace, remote control, orchestration을 하나의 작업 표면으로 묶습니다.

3

믿을 만한 기록이 쌓인 프로젝트는 agent에게 인수인계할 수 있습니다.

Closing

질문은 “어떤 IDE를 쓸까?”가 아니다

내 프로젝트를 agent가 이해하고 이어받을 수 있는 운영 환경으로 만들고 있는가?

이 질문이 앞으로 개발, 연구, 운영 환경에서 더 중요해질 것입니다.
