넘쳐나는 정보의 시대에서
살아남는 법

문제는 좋은 정보가 없어서가 아니라,
좋은 정보를 다 보기에는 시간이 부족하다는 것.

정보 수집을 자동화하는 것이 아니라,

일정

오늘 중요한 일정과 준비해야 할 것.

응답

내가 답해야 하는 메시지와 놓친 알림.

병목

내가 막고 있는 업무와 확인해야 할 사람.

Agent Control Loop

agent가 사람의 손을 떠나려면
제약, 상태, action이 명확해야 한다

agent에게 일을 맡긴다는 것은 단순히 “계속 해봐”라고 말하는 것이 아닙니다. 평가 기준, 하지 말아야 할 제약, 현재 상태, 가능한 action을 명확히 정의해야 합니다.

학습 실행→ wandb metric 기록→ 상태 확인→ 지속or 중단 / 개선→ 재실험
agent가 자율적으로 움직이기 위해서는
평가 기준, 제약 조건, 상태, action의 정의가 먼저 필요하다.

개인과 집단을
agent로 녹여내기

앞으로 중요한 질문은 개인과 조직의 작업 맥락을 어떻게 agent 안에 녹여낼 것인가입니다.

“이거 왜 이렇게 했지?”

Explicit vs Tacit Knowledge

문서로 남는 지식과
작업 과정에 녹아 있는 지식

형식지 문서화되고, 검색되고, 공유되는 수면 위의 지식
암묵지 작업 과정, 시행착오, 판단 기준 속에 숨어 있는 더 큰 맥락
형식지는 잘 보이지만 일부에 가깝고, 실제 업무 맥락의 많은 부분은 암묵지로 남아 있습니다.

실제 업무에서 중요한 지식의 상당 부분은 암묵지에 있지만, 대부분은 제대로 기록되지 않거나 다시 찾아오기 어렵습니다.

The Paradox

AI가 개인 생산성을 올릴수록
조직의 지식 전이는 어려워질 수 있다

개인은 AI와 대화하며 빠르게 문제를 해결하지만, 그 과정은 로컬 세션이나 특정 provider의 대화 기록 안에만 남습니다.

개인

시행착오, 학습, 의사결정 맥락이 빠르게 쌓임.

조직

최종 코드와 문서만 보고, 왜 그렇게 되었는지는 알기 어려움.

Context Portability

provider가 바뀌어도
작업 맥락은 이어져야 한다

다른 PC로 옮기거나, Claude에서 GPT로 넘어가거나, Cursor에서 다른 agent 환경으로 이동할 때 context는 쉽게 끊깁니다.

context는 몇 줄의 요약이 아니라,
파일, 시도, 실패, 에러, 피드백, 가정, 결정의 총합이다.
Project Memory

agent와의 협업 기록도
프로젝트의 자산이 되어야 한다

남겨야 할 것

  • 주요 의사결정
  • 시도했다가 실패한 접근
  • agent와 나눈 중요한 대화 요약
  • 현재 작업 상태

이어받아야 할 것

  • 다음 agent가 알아야 할 context
  • 프로젝트별 작업 방식
  • 반복 문제와 해결 패턴
  • 암묵적 판단 기준

공유하기 쉬움

로컬 브라우저에서 바로 열 수 있고, 정적 파일로 올리면 링크 하나로 공유할 수 있습니다.
